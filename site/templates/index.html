What OpenADR is for

A utility or grid operator needs flexible load to move: charge later, curtail now, follow this price curve. OpenADR is the standard it uses to say so. A VTN (Virtual Top Node) publishes programmes and events; a VEN (Virtual End Node) — a charge point, a battery, a heat pump, a building controller — reads them, acts, and reports back.

Version 3 replaced 2.0b's SOAP with REST and JSON. Version 3.1, released in 2025, added push over MQTT, object privacy, and plain string targets. This crate implements 3.1, and ships both ends of it. The protocol in fifteen minutes →

Running in under a minute

{%- filter markdown(inline=false) | safe %} ```console $ brew install hupe1980/tap/openadr # or: cargo install openadr --features vtn,client,internal-auth,conformance $ openadr dev VTN http://127.0.0.1:3000/openadr3/3.1.0 (in memory — gone when you stop it) Inspector http://127.0.0.1:3000/_inspect#… Seeded dynamic-price 24 h price curve, rolls forward every 15 minutes capacity-limit an event in 2 minutes, and one for feeder-7 that ven-1 cannot see $ source .openadr-dev.env $ openadr watch events # prints only when something changes $ openadr trigger event # a capacity limit, one minute out $ openadr conformance --report report.html ``` {% endfilter %}

A VTN with a business-logic and a VEN client, data that moves, and the inspector — a page that shows the timeline, which events the VEN can and cannot see, and every delivery. Every error a command prints ends with openadr explain and the name to look up. CI holds this to under 60 seconds from start to a VEN reading a price.

For a real deployment, openadr vtn --database ./openadr.sqlite --client-hashed … is every endpoint, an OAuth2 grant with Argon2id-hashed secrets, object privacy, durable storage and a notification queue in one binary; a postgres:// URL makes it the multi-instance one.

And a VEN that acts on what it reads

{%- filter markdown(inline=false) | safe %} ```rust let ven = VenRuntime::with_meter(client, config, HouseMeter); ven.register().await?; // idempotent, and checks the VTN's clock loop { ven.sync().await?; // conditional: a quiet cycle is a 304 if let Some(segment) = ven.active_at(ven.now()) { act_on(&segment.payloads); // priority already resolved } ven.submit_due_reports().await?; // each window filed exactly once ven.wait_for_work().await; // wakes early on an MQTT notification } ``` {% endfilter %}

Registration, resource reconciliation, one conflict-resolved timeline per programme, randomizeStart applied from a seed, a clock-skew guard, and report scheduling that survives a restart — across a looping tariff, against intervals the event never lists, summing an aggregate report and describing its units. What the load does and what the meter reads are yours; the rest is not your problem.
